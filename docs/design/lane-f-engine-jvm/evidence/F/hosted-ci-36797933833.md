## jseval tree-stop fixture

F-4 (`332f60021`) removed the orphan-Worker sweep, not the tree-stop ordering.
`scripts/jseval/jseval/backend.py:566-594` still performs synchronous Windows
`taskkill /PID <pid> /T /F` before `unregister_backend`. That ordering remains the
test's intended contract; restoring the removed process scan would not fix it.

The fixture patched `jseval.backend.os.name`, mutating the shared `os` module.
On Linux this also switches `pathlib.Path` to `WindowsPath`. Registration calls
`Path(override)` (`scripts/jseval/jseval/run_register.py:69`); constructing a
WindowsPath on Linux raises, and registration intentionally catches bookkeeping
exceptions (`:183`). No record exists when the subprocess spy runs, hence
`[False]`. Windows local runs cannot expose that platform mismatch.

Fix: replace only the backend module's `os` binding with a mock, choose `nt`
there, and leave filesystem platform behavior native. The regression now also
asserts successful record creation and the exact tree-stop command, retaining
both the during-stop existence check and post-stop absence check
(`scripts/jseval/tests/test_run_register.py:238-257`). A deliberate in-memory
mutation that unregisters before calling the original stop function fails this
regression, proving the ordering check still fires.
