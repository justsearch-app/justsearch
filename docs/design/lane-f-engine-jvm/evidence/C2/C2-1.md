## Implementation and decisions

- The app-api `OperationStore` port is injected explicitly into EngineRoot and
  HeadAssembly. HeadlessApp opens one SQLite implementation before the async fork;
  LauncherEnvironment owns its corresponding scoped instance. Neither half closes
  the borrowed store. Normal shutdown closes it after a confirmed index drain.
- Failed index drain retains both the store and the data-directory instance lock.
  A successful cleanup retry may close them; otherwise process termination owns
  final release. Startup cleanup waits at most five seconds for the producer;
  cancelling its future does not claim that its thread stopped.
- Schema1 in operations.db includes the agreed D1 fields and singleton recovery
  fence. Existing jobs.db becomes schema15 with nullable content_hash; existing
  owner, recoverability and reconciliation identities remain unchanged.
- Both stores inspect a private main+WAL copy before writable setup. SQLite mode=ro
  can write SHM, so opening originals could violate byte-preserving future-version
  refusal. Copying uses bounded temporary disk proportional to one DB+WAL; it is
  deliberately a quiescent-startup operation, not an online snapshot authority.
  This is simpler and safer than hand-writing WAL checksum/commit parsing.
- Quarantine uses one timestamped `.pending` directory, resumes every remaining
  artifact there and renames it complete before creating the replacement. A new
  directory per restart split the original main and sidecars, so the existing
  preservation-directory name now distinguishes incomplete work. No extra journal
  or marker file exists. The completed directory witnesses the expiry fence until
  replacement metadata commits. Health reports the preserved set and lost history.
- One migration transaction now owns both the version ladder and current-version
  privacy repair. DDL and user_version commit together. Unchecked failures roll
  back; an uncertain rollback closes the connection instead of enabling auto-commit.
- The updater permits incoming supersets while preserving every installed identity.
  `--compat-baseline` emits the prior release's set with current target formats.
  Source verification corrected the draft: old-shell intent expectations came
  from that descriptor, not the successor register. The installed shell validates
  each inherited expectation and expands to its full register before exact Engine
  request/response reconciliation. New stores cannot escape target checks.
