# Lane F stage D1 — reconfigure, generations, readiness: implementation checklist

Written from the three inputs 17.6 requires: the stage's row in `design.md` 17.3, `verified-facts.md`,
and a fresh code-verified read. First drafted 2026-09-09 at `be47faa40` (the stage B head) and
**rewritten 2026-09-10 at `90843f475`** (the C1 head `4229f1091` plus the C2 design commit) after
four read-only audits re-resolved every citation by content; the audits are preserved verbatim in
[`evidence/D1/regrounding-2026-09-10.md`](../evidence/D1/regrounding-2026-09-10.md) and every
`file:line` below is at `4229f1091` unless it names a C2 document. `design.md` is cited by section.
C2 lands before D1 and its contract with D1 is in
[`evidence/C2/operations-store-design.md`](../evidence/C2/operations-store-design.md) §1.3 to §1.8;
this checklist cites it and re-decides nothing there.

Stage D1 in one line (17.3 row D1, as amended 2026-09-10): **one Engine component model that is
both the recomposable registry and the readiness authority; reconfigure as an operation whose
components compose through it with "only success persists"; live generation activation in two
flows, Flow A (same encoders, replacing today's restart at cutover) and Flow B (a generation-bound
change, encoder set B beside or in place of set A); start deadlines, local recovery and bounded
escalation on the component model; the reason-code vocabulary re-cut; the harness that feeds E's
lifecycle rows.**

shared JDK-only handshake owns operation and migration reached/release files;

  schema2 and manifest are projections of its captured snapshot; the existing
  diagnostic dimensions remain diagnostic evidence. Mutable WorkerCapability and

### D1-1 — the Engine component registry: one substrate for recomposition and readiness

Design 7.4 (recomposable registry), 7.6 (readiness by component), 3.2 (core interface, root
binding). A contract in `core` (`io.justsearch.core.component`, beside `core.execution`),
implemented in `app-engine`, constructed in `EngineRoot` as a field beside `executors`
(`EngineRoot.java:52-55`) and handed to the index half through the widened `serverFactory`
(`:88-89`, `:199-201`) and to the front at `:249-251`. The precedent is `EngineExecutorRegistry`,
including its typed refusal shape, its sorted immutable snapshot and its policy loaded from the
classpath-staged `retained-state.v1.json`; **not** `GpuSchedulingGauge`, which is created in
`KnowledgeServerBootstrap` (`:102-103`) and carries no lifecycle.

Contract: `register(ComponentSpec) -> ComponentHandle`; `snapshot()`; `applyLock()` (one
`ReentrantLock` with `tryLock`, the attempted-configurations permit); `close()`. A spec carries
`name`, `essential`, `dependencyKeys` (config keys), `composeCapability`
(`BESIDE | IN_PLACE | CHOOSES_PER_APPLY`), `startDeadline`, `recoveryBudget`. A handle carries
`state` (`ABSENT, STARTING, READY, RELOADING, FAILED, UNAVAILABLE`), `reasonCode`,
`stateSince` (wall and monotonic), `appliedVersion`, `desiredVersion`, `lastCompose`
(mode, reason, free bytes, footprint), `recoveryAttempts`, `evidence`; `transition(...)`,
`setAppliedVersion(...)`, and listener registration for the projections of D1-2. Four
components register: `api` (front), `index` (`KnowledgeServer`), `encoders` (the serving
`EncoderSet`, D1-12; at D1-1 the existing surface), `generative` (`InferenceLifecycleManager`).
The registry activates `attempted-configurations` from the apply lock. D1-9 activates
`representation-generations` when its live accounting exists, and D1-12 activates
`co-resident-encoders` when encoder sets exist; declaring the component model does not
activate either future producer.

**Acceptance:** a coverage test asserts every component the root wires with a config dependency
is registered, with an exception list and a vacuous-pass floor of 4; a test asserts a component's
applied version changes when a declared key's applied value changes and does not when an
undeclared key changes; a test asserts a second `applyLock` holder is refused and the
`attempted-configurations` snapshot count reads 1 while held; `EngineResourcePolicyTest:25-38`
updated only for the producer activated by this item (it is the drift check); `:modules:core:test`,
`:modules:app-engine:test` green.

### D1-3 — the config-apply register, applied versions, and "the index tells the encoders what to be"

Design 7.4 (generation-bound, restart-required; the applied revision is computed). A new
`governance/config-apply.v1.json` with one row per unique key in `EnvRegistry` and
YAML-only `ConfigKey` (currently277 keys after12 aliases and14 justified retirements):
`applyScope ∈ {hot, component:<name>, generation-bound, restart-required}`. Its **semantics**
