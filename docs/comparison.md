# JustSearch — competitive comparison survey

> All facts verified 2026-07-14 unless noted; this is a living document — corrections via
> [issues](https://github.com/justsearch-app/justsearch/issues) are welcome and will be credited. Every cell is
> sourced in the per-row footnote blocks; "Not documented" means we checked official sources and found no
> statement — it is not a euphemism for "no".
> JustSearch's network disclosures below reflect the current product; competitor rows retain that survey date.
>
> **Headline finding:** this survey **narrowed our own claim**. Self-hosted server stacks — RAGFlow, Open WebUI,
> QAnything — each combine {true hybrid retrieval × fully offline × multilingual × OCR} as Docker/server
> deployments. What survives, as far as we know: no **single-install desktop app** ships all four out of the
> box, no surveyed tool documents a SPLADE learned-sparse retrieval leg, and no MCP retrieval server documents
> OCR or cited answers. Details in the [Verdict](#verdict-does-the-uniqueness-claim-survive) section.

---

## What this document is

JustSearch claims to occupy a specific feature cell: **true hybrid retrieval** (lexical + dense + learned-sparse, with cross-encoder reranking) **× local indexing and inference × multilingual × OCR for scanned documents**, packaged as a Windows desktop app with an MCP retrieval backend. A claim like that is only worth anything if it is checkable, so this page is the public version of the survey behind it: one row per tool a buyer would realistically consider, every cell sourced, every competitor represented at its current best — including the places where it beats JustSearch.

JustSearch's own weaknesses, stated up front and repeated in its table row: **Windows-only; alpha (0.1.0); unsigned installer (SmartScreen warnings); ~9 GB model download; very young and unproven (repo created June 2026, 2 GitHub stars at survey date); retrieval benchmarked only in English, German, and French** despite a 70+-language embedding model.

## Matrix

Legend: **Offline** = indexing, retrieval, and built-in inference can work without a network connection after setup/model download. This describes processing capability; background update checks and optional integrations are called out separately. "Optional" = local operation possible but cloud is the default or an equal path. **Retrieval** names the actual components. **MCP** = Model Context Protocol; "server" means the tool exposes retrieval to external AI clients, "client" means it consumes other MCP servers.

## Per-competitor notes

Neutral register throughout: what it is, where it beats JustSearch, where JustSearch differs.

### Everything (voidtools)
A Windows filename search engine with a real-time NTFS/ReFS index, maintained since 2004. **Where it beats JustSearch:** instant as-you-type results over millions of files with near-zero RAM and CPU, twenty years of proven stability, and no multi-gigabyte model download — for "find the file whose name I half-remember," nothing in this survey is faster. **Where JustSearch differs:** Everything searches names, not meaning; its content search is unindexed in 1.4 and secondary even in the 1.5 beta, and it has no semantic retrieval, OCR, answers, or MCP endpoint. The two tools are complements more than competitors.

### Recoll
A GPL full-text desktop search engine (Xapian) maintained for roughly two decades by Jean-François Dockes. **Where it beats JustSearch:** format breadth and extraction robustness earned over 20 years — email stores including Outlook .pst/.ost, archives, attachments nested to arbitrary depth — plus mature OCR of image-only PDFs via Tesseract/ABBYY, per-language stemming across many languages, and Linux/macOS support. **Where JustSearch differs:** Recoll is lexical; its dense-embedding branch is an explicitly experimental opt-in that its author calls scaffolding, and he has documented that reranking proved impossible on his consumer hardware. Recoll finds documents containing your words; it does not retrieve by meaning, rerank, or answer questions. Note also its Windows binary asks a small (waivable) fee, and OCR on the Windows port is not documented.

### Khoj
An open-source (AGPL) self-hosted "AI second brain" with web, desktop, Obsidian, and Emacs clients. **Where it beats JustSearch:** four-plus years of history, a 35k-star community, mature cross-encoder reranking, custom agents, scheduled automations, and clients on far more surfaces than Windows. **Where JustSearch differs:** Khoj's retrieval is dense-plus-rerank with no lexical leg, it has no OCR (its PDF path is text-layer extraction), multilingual support is an undocumented-benchmark model swap requiring a full re-index, telemetry is on by default, and it ships no official MCP interface. Buyers should also weigh that Khoj Cloud was sunset on 2026-04-15 and the maintainers have publicly shifted to new products (Open Paper, Pipali); self-hosting remains supported but the release cadence has slowed.

### AnythingLLM
Mintplex Labs' MIT-licensed all-in-one AI workspace, available as desktop apps for Mac, Windows, and Linux plus a multi-user Docker deployment. **Where it beats JustSearch:** platform coverage, enormous model/provider flexibility (any llama.cpp/Ollama/cloud backend), built-in OCR for scanned PDFs and images (native since v1.7.4, multilingual OCR since v1.7.5), agent tooling with MCP-client support, a 63k-star community, and monthly releases. It is the closest desktop app to JustSearch's cell. **Where JustSearch differs:** AnythingLLM's retrieval is vector-only — no BM25/lexical leg is documented, so exact terms, codes, and names can be missed; its reranker is optional, LanceDB-only, and the model is not named in docs; retrieval multilingualism is not benchmarked (default embedder is English-centric); and it consumes MCP tools but does not expose retrieval as an MCP server. Telemetry is on by default (opt-out).

### LocalSynapse
A Windows local search tool with a native MCP server — nearly the same product category as JustSearch, and the closest match in this survey on the offline+hybrid+MCP axes. **Where it beats JustSearch:** first-class Korean/CJK handling, email formats (.eml/.msg/.mbox) and structure-preserving spreadsheet reads today, an explicit zero-telemetry/air-gap posture, and a rapid release cadence. **Where JustSearch differs:** LocalSynapse documents no OCR and no reranker, has no built-in LLM answers (it is a search/MCP tool, not an assistant), its embedding model is unconfirmed in official sources, and — significantly for an "open source" positioning — its source tree is no longer published from v2.15.0 onward; current versions are binary-only releases under a repo that carries Apache-2.0 for historical code.

### LM Studio
A polished, closed-source, free-including-work local LLM desktop app with a large model catalog. **Where it beats JustSearch:** three years of maturity, macOS/Windows/Linux coverage, a companion iOS app, MCP hosting, a local API server, and general polish. **Where JustSearch differs:** LM Studio's "Chat with Documents" is a basic RAG whose architecture is not documented; no hybrid retrieval, reranking, OCR, or citations are documented, and file support is effectively .pdf/.docx/plain text with a 30 MB cap. It is a model runner first and a document tool second.

### Jan
An Apache-2.0 open-source desktop assistant (menloresearch) on Windows, macOS, and Linux. **Where it beats JustSearch:** cross-platform, ~43.5k stars, monthly releases, and inline numbered citations shipped since v0.8.0. **Where JustSearch differs:** Jan's RAG is vector-only (sqlite-vec, cosine, top-3) with no lexical leg, no reranker, and no OCR (text-layer PDF extraction only).

### GPT4All (Nomic)
The MIT-licensed desktop app whose LocalDocs feature popularized on-device document Q&A. **Where it beats JustSearch:** a very large installed base, cross-platform support, and a fully on-device default embedder with file-level source citations. **Where JustSearch differs:** retrieval is vector-only with 512-char snippets and top-3 recall, there is no OCR, no MCP, and — the key buyer fact — the last release was v3.10.0 on 2025-02-25, with no maintainer activity since; the project is effectively unmaintained as of this survey.

### Msty / Msty Studio
A proprietary, polished local-first AI desktop app. **Where it beats JustSearch:** cross-platform coverage, ingestion of unusually many source types (Obsidian vaults, YouTube transcripts, folder sync), MCP client tooling, and a free tier that includes local RAG. **Where JustSearch differs:** retrieval is vector-only, the reranker requires a cloud Jina API key (which breaks a fully-offline posture when used), OCR is not documented, commercial use requires a paid license ($149/user/yr), and the source is closed.

### File Brain
A young (Nov 2025) GPL-3.0 project pairing Typesense keyword/fuzzy search with a multilingual dense embedder and Tika extraction. On paper it is the closest indie project to JustSearch's cell: keyword + multilingual dense retrieval, advertised OCR, claimed 100% local indexing. **Where it beats JustSearch:** cross-platform (Python/Docker), a very broad extraction surface via Tika, and cloud-source connectors (Drive/Dropbox/OneDrive) in its paid tier. **Where JustSearch differs:** no reranker or learned-sparse component is documented, retrieval fusion is not documented, chat/citation behavior and the advertised MCP support are paid-tier promises without published implementation detail, no benchmarks exist, and the repo has been quiet since v0.1.28 (2026-04-10). Its multilingual and OCR claims are plausible but thinner-documented than the tools in Tier C.

### LocalSpider, LaSearch, SpotMyFile, Onit (indie status check)
LocalSpider is an unreleased waitlist product (claimed offline semantic search, $45 lifetime; no repo or version history found). LaSearch is a macOS-Apple-Silicon-only free beta with a one-page site and no documented internals — there is no Windows product. SpotMyFile is a dormant 2-star hobby repo (hybrid BM25+dense on paper; last commit June 2025). Onit is a real, active macOS AI sidebar, but it is not a file-search engine and is out of category. None of the four is a shipping Windows competitor today; we list them because they appear in "local semantic search" search results.

### MCP retrieval servers (Tier B)
A note on names: the two repos literally called `mcp-local-rag` do different things — **nkapila6/mcp-local-rag is a web-search MCP server** (requires internet; not local-file RAG), while **shinpr/mcp-local-rag** is the actual local-file competitor. shinpr's server is the tier's standout for simplicity: one `npx` command, a ~90 MB model, cross-platform, weekly releases — against JustSearch's ~9 GB and Windows-only installer, that lightness is a genuine advantage for developers who just want retrieval behind Claude or another client. It lacks a cross-encoder reranker, OCR ("Not yet: Excel, PowerPoint, images"), and defaults to an English-first embedder. **lyonzin/knowledge-rag** is architecturally the closest MCP server to JustSearch — real BM25 + dense + RRF + cross-encoder rerank, three transports, ~20 parsers — but it explicitly disclaims OCR and its multilingual mode is an unbenchmarked model swap. **Minima** (1,050 stars) offers a fully on-premises mode with a BAAI cross-encoder reranker but is vector-only, Docker-Compose-heavy, and has had no commits since January 2026. The remainder (patakuti's report-generating server, the abandoned local-docs-mcp and rust-local-rag) are small or inactive; the tables carry the details. Across the entire tier, **no MCP retrieval server documents OCR for scanned documents**, and all return raw chunks rather than cited synthesized answers (answer generation is delegated to the MCP client by design — JustSearch's `justsearch_answer` tool differs by synthesizing cited answers server-side).

### RAGFlow, Open WebUI, QAnything, Kotaemon, Onyx, LocalGPT (Tier C)
These self-hosted platforms are where JustSearch's uniqueness claim goes to die in its broad form — see the Verdict below. **Where they beat JustSearch:** RAGFlow's DeepDoc is a more extensively documented document-understanding pipeline (OCR + layout + table-structure recognition) than anything else surveyed, and it is mature and actively maintained; Open WebUI has a 145k-star community, a release every 2–3 weeks, twelve vector-DB backends, nine extraction engines, and the most configurable RAG pipeline in this survey; Kotaemon ships a clean hybrid + rerank + citation pipeline with a web UI; Onyx adds enterprise connectors (Drive, Slack) at scale. **Where JustSearch differs:** every 4/4 tool in this tier is a Docker/server deployment that the user must compose, provision models for, and configure — hybrid search and reranking are off by default in Open WebUI and its default embedder is English-leaning; RAGFlow needs HuggingFace pre-caching for a true air gap and has no official ARM64 image; QAnything's multilingualism is Chinese-English and its last release was August 2024. JustSearch's position against this tier is packaging, defaults, and a native MCP server in a single Windows installer — not capability that is unavailable elsewhere.

### NotebookLM, Microsoft Copilot, ChatGPT (Tier D)
**Where they beat JustSearch:** frontier-model answer quality (NotebookLM runs Gemini 3.5; its passage-level inline citations with hover quotes are the best-documented citation UX in this survey), zero setup, zero local hardware requirements, and — for M365 Copilot — permission-aware grounding across an organization's entire Microsoft Graph inside the Office apps people already use. **Where JustSearch differs:** none of the three can operate offline, and all involve transmitting file contents to the vendor. The policies differ materially and are worth quoting precisely: NotebookLM personal accounts get a no-training commitment (except feedback); Copilot consumer uploads are stored up to 18 months but not used for training; ChatGPT consumer tiers (Free/Go/Plus/Pro) train on content by default with an opt-out, while Business/Enterprise do not train by default. For air-gapped, regulated, or simply private corpora, this tier is out of scope by definition — that is the contrast JustSearch exists to serve, and it is the honest framing: you trade frontier model quality for locality.

## Verdict: does the uniqueness claim survive?

**The README claim evaluated in the original survey did not survive. The narrower claim is below.**

The README claim evaluated in the original survey said JustSearch combines "{true hybrid retrieval × fully offline × multilingual × OCR} at once" and that "we're not aware of another local tool that combines these." This survey found three local tools that combine all four:

1. **RAGFlow** (Apache-2.0, Docker Compose) — hybrid weighted keyword + vector retrieval with fused reranking, fully self-hostable with local models via Ollama/Xinference, built-in local DeepDoc OCR, and documented local serving of the multilingual bge-m3 embedder. The one caveat: first-run OCR weights download from HuggingFace, so a true air gap requires one-time pre-caching. This is the clearest counterexample.
2. **Open WebUI** (Docker/pip server) — BM25 + vector hybrid (`ENABLE_RAG_HYBRID_SEARCH`), local cross-encoder reranking (`RAG_RERANKING_MODEL`), local OCR via Docling/Tika/PaddleOCR, and any local Sentence-Transformers embedder including multilingual ones. Caveats: hybrid and reranking are **off by default**, and the default embedder is English-leaning — the cell is reached by configuration, not out of the box.
3. **QAnything** (NetEase Youdao, Docker) — BM25 + embedding retrieval, BCE reranker, built-in PaddleOCR, explicit unplug-the-network-cable offline support. Caveats: multilingualism is Chinese-English cross-lingual rather than broadly multilingual, and the last release was August 2024.

**Kotaemon** reaches the cell via configuration (hybrid + rerank + local OCR loaders; multilingual embedder pluggable but undocumented), and **LocalGPT v2** is 3/4 (hybrid + rerank + multilingual default embedder, but PDF-only with no OCR).

### What does survive

A narrower, still-checkable claim survives this survey:

> **Among single-install desktop applications, we found no tool that ships {lexical + dense + learned-sparse hybrid retrieval with cross-encoder reranking} × {local indexing and inference} × {multilingual} × {OCR} out of the box.** Every tool we found that combines all four axes is a self-hosted Docker/server deployment requiring technical setup, and in Open WebUI's case the combination is opt-in configuration rather than default behavior. The tools that come closest are listed below — if you know another, open an issue and we will add it.

The nearest misses, by deployment class:
- **Desktop apps:** AnythingLLM (3/4 — offline + OCR + optional reranker; vector-only, no lexical leg); Cherry Studio (~2.5/4 — local OCR options; embedding-only retrieval, cloud default preprocessor); Msty (vector-only, cloud-key reranker, no documented OCR).
- **Windows search + MCP tools:** LocalSynapse (3/4 — offline + BM25/dense hybrid + native MCP server; no documented OCR or reranker, source now closed); File Brain (advertises keyword + multilingual dense + OCR; no reranker documented, v0.1.x, quiet since April 2026).
- **MCP servers:** lyonzin/knowledge-rag (hybrid + cross-encoder + offline; explicitly no OCR); shinpr/mcp-local-rag (hybrid-lite, no OCR, English-first).

Two further factual differentiators held up across the whole survey and can be stated without hedging: **no surveyed tool of any deployment class documents a SPLADE-style learned-sparse component as a third retrieval leg**, and **no surveyed MCP retrieval server documents OCR for scanned documents or serves cited synthesized answers**.

### Required edits to the README before publication

- Replace "we're not aware of another local tool that combines these" with the narrowed desktop-app claim above, and **name RAGFlow, Open WebUI, and QAnything** as local server-class tools that do combine the four axes (the README promises to list such tools; here they are).
- The "fast-but-literal" framing of Recoll should be softened or footnoted: Recoll has shipped OCR for image-only PDFs for years and has broad multilingual lexical support; it is literal, but not featureless.
- Keep the honest weaknesses row wherever the claim is made: Windows-only, alpha, unsigned installer, ~9 GB models, 2-star young repo, benchmarked only EN/DE/FR.

## Sources & method

**Access date for every source: 2026-07-14** (a handful of GitHub metadata checks reflect repository state on 2026-07-13–14; where page summaries conflicted, dates were cross-checked against the GitHub API).

**How we searched.** Five parallel research passes: (1) classic local search tools + indie Windows semantic-search products; (2) Khoj / AnythingLLM / LocalSynapse in depth; (3) local LLM desktop apps' RAG features (LM Studio, Jan, GPT4All, Msty, Open WebUI); (4) MCP local-retrieval servers, including MCP directory sweeps (mcpservers.org, PulseMCP, Glama, LobeHub) for servers beyond the seed list; (5) cloud reference points plus a dedicated adversarial pass whose explicit goal was to falsify the uniqueness claim (candidates: RAGFlow, Onyx/Danswer, Kotaemon, QAnything, PrivateGPT, LocalGPT, Reor, Curiosity.ai, Paperless-ngx, Nextcloud Context Chat, Cherry Studio, DocAnalyzer, and open-ended searches such as "offline hybrid search BM25 embeddings OCR"). Primary sources were preferred in this order: official docs > project README/source code > GitHub API metadata > vendor blog/changelog > reputable secondary press (used only for pricing news and NotebookLM model history). Where a fact rests on a secondary or third-party source, the row footnote says so.

**What we could not verify** (kept as "Not documented"/flags rather than guesses):
- LocalSynapse's embedding model (BGE-M3/ONNX appears only in a third-party MCP listing) and its possible macOS builds (homepage vs README conflict).
- LM Studio's built-in document-chat embedder and retrieval internals; its May-2023 first-release date rests on secondary sources.
- Msty's vector store (secondary source says SQLite) and its citation UI details.
- AnythingLLM's reranker model name (not in official docs).
- File Brain's citation grounding and the implementation of its advertised Pro-tier MCP support.
- LaSearch and LocalSpider internals (architecture, models, OCR) — neither publishes technical documentation.
- ChatGPT Go's exact US price; whether ChatGPT auto-cites uploaded files; NotebookLM tier-specific model variants.
- Open WebUI's docs site returned HTTP 403 to our fetcher; all Open WebUI doc citations were verified against the rendering source repo (github.com/open-webui/docs) instead.
- Curiosity.ai's current consumer product (documentation removed/404).
- Whether any surveyed tool has published multilingual retrieval benchmarks: none has; all multilingual claims in this document are model-inherited or vendor-claimed unless marked "benchmarked".
